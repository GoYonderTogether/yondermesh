四模块怎么写

1. 目标 (Goal)：成功长什么样 + 约束。例："给一天全部 session 生成结构化汇总，不能漏报失败任务。"

2. 上下文 (Context)：每次循环必须读的固定文件。例："读 ARCHITECTURE.md、docs/features.yaml、src/mcp/ 现状。"

3. 行动约束 (Action)：允许哪些工具/命令、能改哪些范围。例："只能改 src/mcp/ 与 tests/；用 vitest 验证。"

4. 观察与反馈 (Observation)：怎么判断做对——测试 + 一个"检查者" sub-agent 对抗审查；失败把错误丢回继续，直到通过。

Prompt：复制给 agent 的提示词，须要求"用 sub-agent 执行 + 自验证到通过才停、不许撒谎"。留空则自动从四模块生成。

verifier：定义"完成"的命令（如 npm test -- mcp），scan 据此判 passed/failed。必须可机器校验。

状态机：draft（人写）→ 人审改 approved → scan 跑 verifier → passed/failed。passed 且有 feature 关联 → 自动把该 feature 置 shipped。
